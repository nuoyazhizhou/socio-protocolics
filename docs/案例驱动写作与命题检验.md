# 案例驱动写作与命题检验

版本：v0.1｜日期：2026-10-23｜中文原稿，英文待译。

本约定落实[AGENTS第九条红线](../AGENTS.md)，适用于全部主题、作者、Agent、旧稿续写和翻译。理论定义仍以[白皮书](../社会系统协议学白皮书.md)为准。

## 文章的研究任务

通过真实事件提出问题、追踪机制，再让证据决定具体主张是否成立、适用到哪里，并评估工程视角是否增加判断。宣传、吸引同道与共同讨论可以是传播目标，但“必须证明框架正确”不能成为研究验收条件。

每篇选一个可检查的子主张，附总源版本、组/RFC、具体位置、条件与身份；“协议学有道理”不能充当待检验命题。发现新问题可以调整目标，须留调整前版本、已知结局和理由；回溯分析不能包装为事前预测。

| 主张身份 | 应检查什么 | 不能混成什么 |
|---|---|---|
| 形式条件命题 | 假设、量词、推导与现实适用条件 | 题设不满足不等于推导错误；故事吻合不代替证明 |
| 经验机制或桥接假说 | 独立测量、过程、竞争解释、可区分观察与误差 | 相关不自动是因果，不显著不自动是反证 |
| 核算定义 | 单位、主体、时期、遗漏、重复与敏感性 | 恒等成立不等于现实净收益为正 |
| 规范目标 | 价值、权利、受影响主体、代价与可行替代 | 有效不自动推出应该采用，故事不证明价值目标 |
| 表达或方法增益 | 同信息下与普通方法的公平比较 | 新词、公式可运行和读者点赞不等于理论增益 |

## 让真实过程承担正文主线

至少一个主案例要讲清：谁在什么时期面对什么问题，原规则怎样运行，发生了什么决定或改变，关键过程怎样展开，可核结果是什么，哪些后果仍未知。决定、行为、引文和数字须有出处；动机只在有材料时作为当事人说法或有界解释，不补写内心、对白和未观察到的场景。

证据应能追溯原作者/机关、文献版本、成文与事件日期、章节/条款/页码/表号、实际阅读范围及来源链。官方文件首先证明规定，项目记录说明过程或自评，研究论文按其方法与分母使用；都不自动替代实际效果。缺结果材料就标缺口，不能从改革通知讲出尚未观察到的成功。

工程概念在需要区分关系时进入，说明映射保留和丢失的性质，比较普通解释是否已覆盖。不先讲完一套抽象概念，再点缀几个真实名字。至少核对一项真实反向材料、同案相反观察或有证据的竞争解释，指出它会改变哪个判断；假想失败只算检验方向，没找到反证也不算支持。

各组继续寻找中国与外国的有利、不利、部分成功和不适用材料；每篇不机械凑四案。四格不是随机或匹配实验，重用同案或转引同一来源不算独立重复证据。

## 起稿与续写都要回读的选题卡

各[主题计划](../research/主题计划/README.md)须维护以下字段，变更时更新卡片与版本，不只保留标题和候选清单。

| 字段 | 必填内容 |
|---|---|
| 目标子主张 | 总源版本、组/RFC、原句或具体位置、条件、认识论身份；作者新增应用另标 |
| 主案例与过程 | 对象、时期、地区、行动者、原规则、关键决定/过程、结果维度、已知结局 |
| 证据链 | 每项关键事实对应的原件与定位、实际阅读范围、当前缺口 |
| 反向材料 | 真实反例、同案差异或有据竞争解释；已取得与待检索分开 |
| 可区分观察 | 支持、拒绝或收窄所需观察；题设不满足、测量不足另列 |
| 普通解释比较 | 既有解释已覆盖什么、工程表示拟增加什么；允许重述或零增益 |
| 理论回写 | 拟改的具体位置与理由、受影响稿件；当前不足时写“暂不修理论” |
| 当前阶段 | 材料表、比较稿、案例稿或概念样章，以及下一份具体材料 |

多问题分别记证据和裁决。引用O4、P3或某组名称，不等于检验整组；只检查004应用边界，不能同时认领005反馈已获证。

## 阶段验收

- **T1材料表：**至少一条可追溯真实事实链、来源身份与关键缺口。只有标题、未读链接或设想不通过。
- **T2比较稿：**子主张及条件、案内过程、真实反向材料或有据竞争解释、拒绝/收窄条件齐备。不能从已知结局倒推机制。
- **T3中文案例稿：**真实主案例撑起叙事，工程映射帮助具体判断，结论由对应证据承重；提交下述回执与来源说明。以概念、模拟算账或真实材料点名为主，标“概念样章／待真实案例重构”，不算T3通过。探索性案例稿可以没有因果效应估计，但须限定结论，不强行等待不存在的量化条件。
- **T4英文对应：**中文通过相应阶段后翻译，保留同一案例、条件、未知与裁决，不用译文强化结论。

材料不足时先做可推进的检索、证据表或有记录的选案调整，无须反复请求批准已明确的写作原则。确实无法取得就交缺口，不编成故事。自动检查能确认文件、编号和文本存在，不能代替叙事、证据和推理的实质审读。

## 每篇必须交的命题回执

| 子主张与总源位置 | 支持及相反证据、定位 | 竞争解释及区分结果 | 裁决与边界 | 拟修订位置或不改理由 |
|---|---|---|---|---|
| 本篇实际检查的一项；原文与作者应用分开 | 来源链不重复计数，未知不补零 | 含义相同登记为重述 | 局部支持／拒绝具体经验预测／收窄适用范围／既有解释已足够／证据不足，可分项并存 | 明确到SSOT条款及衍生稿，或写当前不足以修改 |

分开裁决“现实事件说明什么”和“框架增加什么”；主案成功不自动证明框架有增益。事实错误先纠正，确需理论变化再增量修总源、速查卡和相关稿并运行[门禁](../AGENTS.md)。没有新增理论结论也如实记录，不为凑修订改理论，不只修改评审报告。

## 文体与证据一起守住

保留短段落、真实困惑、鲜明判断、对照与工程比喻，关键条件放在相应判断旁边。虚构引子和演示数字首次出现标清，不占据事实主线或承担现实结论。正文就近给来源，较长方法放来源说明；承重事实未核实就改、换案或暂缓案例稿，不能用“欢迎指正”代替核查。

读者既能带走一个检查办法，也能指出它在哪种观察下失效；传播、批评与共同修订由此接到同一个研究问题。


## 生成卡与三种检验分开登记

以[白皮书生成与证据卡](../社会系统协议学白皮书.md#rfc-evidence-cards)定位子主张；案例研究回执需分别写必要性、充分性和最小性本次检查哪一项、另两项是否未检查。缺少某机制但仍达标可以反对必要性；机制存在仍失效只在其充分性条件满足时构成反证；最小性须比较删减或替代方案。真实反向材料、假想压力情境和题设不满足分别登记。规范目标的可取性、实施效果及形式模型各用对应证据；一个案例的正反结果不能一并算成同一预测获证。
