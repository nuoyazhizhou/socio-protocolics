# 中文先行、案例配对与写作约定

版本：v0.4｜日期：2026-10-27｜语言：中文原稿，英文待译。

本约定从既有中文出版计划与样稿中提炼，按当前仓库状态重新编排。历史底稿、完整审校过程和来源备份继续留在本地。框架定义以[中文白皮书](../社会系统协议学白皮书.md)为准。

## 中文先行

面向读者的项目介绍、文章、框架导读、研究卡、材料说明和贡献说明，先有中文版本，再制作英文对应版。第三方原文、程序、配置、稳定编号和数据字段保留原有形式，并提供必要中文解释；不另造一套翻译后的代码或原典。

每份译文记录：对应中文文件、中文版本或内容哈希、翻译版本、翻译日期、检查状态、尚未同步的改动。中文更正后，英文可以标为待同步，不能继续无条件标作最新。英文发现实质问题时先修中文源，再同步；翻译不能自行成为另一套权威定义。

先整理双语术语表。六组核心命题不能翻回六条已证普遍定律；公设、条件命题、机制假说、核算定义和规范选择分别保留身份。特别检查可能/必须、相关/因果、作者主张/独立证据、立法/实施/效果等区别。

## 同一主题按用途分支

先区分主题、写作目的、语言和版本。一个胡适主题可以同时有研究说明、知乎长文、Reddit讨论稿及学术论文；它们是不同交付物。版本号只在同一用途分支内比较，不能因研究稿v0.6小于知乎稿v1.0就判断前者过时，也不能按研究稿的文体要求淘汰传播稿。

每个用途分支登记目标读者、要解决的问题、希望读者采取的行动、主要文件、版本及实际状态。同一用途有多个过程稿时，按内容完整性、目标匹配、独有材料和已知错误选择一个主要工作底本；其余转历史归档或明确标为补充素材。不同用途确有价值时分别保留，不为了文件少而合并成一篇。

| 交付用途 | 本项目拟完成的任务 | 选择与维护重点 |
|---|---|---|
| 研究说明／探索文章 | 展开材料、机制、竞争解释和改判条件，供接续研究 | 来源定位、未知与命题回执；不因名为研究稿就登记为学术论文或T3通过 |
| 知乎长文或短答 | 从具体争议进入，让读者理解一个判断方法并愿意继续讨论 | 叙事、节奏、工程比喻和可带走的问题；长短形态分别记录，不以篇幅决定优劣 |
| Reddit讨论稿 | 围绕明确问题邀请指定社区补充、反驳或比较 | 先写中文改编提纲，交代陌生背景、讨论问题和社区适配；未写成就标待制作，不把中文长稿改个文件名当成英文稿 |
| 学术论文 | 回答限定问题，并提交相对既有研究的贡献与相应方法和证据 | 研究问题、文献、识别或论证、材料与限制；没有完成研究时只登记计划，不把传播文章重命名为论文 |

不同用途可以调整结构、长度、语气、背景解释和引用呈现；史实、来源与证据强度共享。传播效果不是机制验证，阅读体验也不必被写成论文形式。关键事实更正及会改变结论的限制须逐稿检查，不能只修研究稿而放任传播稿继续保留已知错误。

平台改编与完整翻译分别标识。完整译文遵守下文案例配对要求；另行改编须记录来源稿和改变的目的，不能标为原稿的完整译文。尚无对应稿时只登记任务，不创建空白成稿或虚构发布状态。

## 中外案例共同出现

每个案例都有中文原稿和英文对应稿。两种语言保留同一组案例与核心比较；可补背景、调整解释顺序，不能在英文中换成另一个案例却仍标为同一篇的完整译文。

中国人物也向外国读者说明“他是谁、原有规则是什么、改变针对什么”；外国人物同样向中国读者补足背景。不要假设所有英文读者都熟悉欧洲或美国历史。

案例按相同问题配对，不能仅凭国别和好坏配额拼接。具体规则见[案例选择与比较方法](../research/案例选择与比较方法.md)。各案的“成功”维度可以不同，但这时只作启发性比较，不能称严格因果对照。

## 案例先行的强制要求

全部主题、起稿、续写和翻译先遵守[案例驱动写作与命题检验](案例驱动写作与命题检验.md)及AGENTS第九条。先回读主题卡，明确子主张、真实主案例、真实反向材料或有据竞争解释、裁决与理论回写位置。

每篇用至少一个展开的真实过程承重；关键事实可溯源，工程概念随后进入。概念讲解、模拟算账和零散真实材料点名不能代替真实案例稿，未达要求标“概念样章／待真实案例重构”。文体参考只继承节奏与表达，不继承样文中的数字或“已核”声明。

## 文章骨架

从一个具体困惑进入，提出范围明确的判断，用作品、文件或过程材料展开。每篇选择一个主导工程模型，解释它保留了什么关系、又没有保留什么。工程术语须帮助推理，不能仅替对象改名。

保留鲜明观点与可读性，把关键条件接在相应判断旁边。虚构场景、模拟数字、他人实证与作者映射首次出现时即标清，不靠文末补救。

每篇至少处理一项可能改变结论的反例或竞争解释。结尾给出可带走的检查步骤及具体参与任务；允许答案是资料不足，不能要求读者先相信整套框架。

## 文末的最小连接

每篇用数个短段说明：

1. 已有研究或史料：原作者、版本、定位，支持什么、不支持什么。
2. 框架位置：直接使用的原语、公设、命题组或RFC；背景关联另列，不挂满全体系。
3. 作者映射：工程对象与社会对象、保留关系和丢失性质。
4. 假设与边界：受众、任务、竞争解释，以及什么观察会迫使修改。
5. 可接手的问题：已有材料、第一份可提交成果、当前缺口。没有成熟卡时标候选。
6. 版本及语言：正文、来源说明、总源位置和另一语言状态；没有生成的文件或网址不造链接。

关键来源同时放在相关正文附近。自家文章与白皮书互链只提供导航，不构成外部证据。

框架引用使用明确编号和原文链接，写成“公设背景 → 主要命题组/条款 → 规范目标或定性延伸 → 未检验部分 → 开放问题”。来源说明另列正文位置；不能只在尾注写“依据协议学”或把3→6→19全套挂名。具体示范见[胡适尾注](../articles/hu-shih/如何评价胡适的作品.md#article-framework)和[全框架索引](框架与案例索引.md)。

## 从例子回到框架

事实更正先修改相应文章；涉及定义或命题的变化，先记录原主张、反对证据、竞争解释和拟改范围，再增量修正总源及受影响衍生稿。方法有效、机制成立和公设合宜是不同问题，不能用文章好评互相替代。

新增案例和译文须加入公开清单，检查链接与文本范围；修改白皮书、速查卡或AGENTS时还按[门禁规则](../AGENTS.md)回归。内部材料和审计证据不因参与写作自动公开。
