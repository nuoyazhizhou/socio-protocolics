# 发布与目录约定

## 公开与本地

公开内容以根目录 `public-files.json` 的逐文件清单为准。白皮书和速查卡保留原路径；`articles/` 放案例及必要来源，`research/` 放可接手的问题，`tools/` 放发布工具。

内部未删节版、对话与讨论记录、原始工作稿、评审报告、审计证据、浏览器缓存、依赖副本、来源原件备份和出版规划保留在本地原位置，并由忽略规则排除。公开的简明修订说明只记录文章变更，不复制内部对话或原始审计。

`.gitignore` 不是保密系统。它防止常规误加，不能阻止 `git add -f`，也不影响已经存在的历史对象。每次发布前还需运行公开清单检查。

## 内容回归、发布范围与导出

```powershell
python -m pip install -r tools/requirements.txt
python tools/verify_all.py
python tools/check_public.py
python tools/export_public.py
```

安装依赖后，`verify_all.py` 检查公开白皮书、速查卡和 AGENTS 的指定结构与文本标记，并执行嵌入式参考引擎的所列数值、阈值、缺失与元数据检查；实际项数以当前运行输出为准。默认不需要内部版；维护者可按 [AGENTS 门禁说明](../AGENTS.md#四-自动化质量门禁verification-gate) 显式指定本地内部版，增加相应检查。脚本不依赖维护者旧目录或脚本位置环境变量。

白皮书保持一个公开正文文件，用9组标签支持按章读取与编辑，操作见[分块指南](白皮书分块读取与编辑.md)。门禁同时核对区块边界；编辑工具默认预览，写入须核对原区块哈希并保留锚点。分块回归另运行`python tools/test_whitepaper_blocks.py`；备份和编辑中间稿保留于`.local`，不纳入公开导出。

`check_public.py` 检查当前索引的文件范围、公开文件是否存在、是否包含写作标记或本机绝对路径，以及 Markdown 本地链接是否落在公开清单内。它不会自动联网核实外链，更不是内容安全或全文事实正确的保证。

`export_public.py` 先做相同的公开范围检查，再把清单中的当前工作区文件复制为新的目录和 ZIP。它不复制 `.git`、内部材料或旧历史，不执行提交或推送，并保存各文件的 SHA-256。工作区文字可以与已提交版本不同，导出清单明确记录这一点。导出不会自动运行内容回归门禁；导出目录可另运行 `python tools/verify_all.py` 和 `python tools/check_public.py --snapshot`。后者不检查 Git 索引。

## 已有历史的边界

本次整理前，本地 Git 已经记录内部版和大量评审材料，而且有多个旧分支。停止跟踪不会清除这些历史；直接推送原工作仓库的历史或备份分支，仍可能带上它们。

公开仓库使用清单内文件初始化独立的 Git 历史，不复制原工作仓库的 `.git`。旧工作仓库的历史保留为本地档案。若要保留旧提交并彻底清理其历史，需要另外规划所有分支、标签和备份的处理。

项目远程地址为 `https://github.com/nuoyazhizhou/socio-protocolics.git`。配置远程与创建本地提交不等于已推送或发布；是否对外推送以维护者明确授权及实际执行记录为准。

## 正文、注释与来源

公开文章保留读者判断结论所需的限制，包括未测量、暂释、样本限制和替代解释。私人写作策略留在本地。去除 `NOTE` 标记不等于完成核查，不得把“目前未核”藏进将被删除的备忘后，继续对读者宣称“全部已核”。

公开来源优先列原作者文本、同期原件、技术标准或原研究，分别写明支持什么、不支持什么。工程类比标明用途；历史材料不因符合框架就升级为因果验证。

## 版本与许可

白皮书v11.2的本次修订发布标识为`v11.2-r20261028`，见[修订记录](修订记录.md)。理论版本与修订快照分开；已有文章按用途保留各自版本。

白皮书的统一版本仍为 v11.2。案例文章与研究卡单独标版本，不因为文章修改就宣称白皮书核心命题完成经验验证。文章修订应保留公开摘要；工作底稿和完整差异可在本地保存。

当前没有代作者选定 MIT、CC BY 等统一许可证。发布平台、贡献授权与第三方引文的使用范围分别处理。

## 在线阅读与自动发布

网站地址为[GitHub Pages阅读站](https://nuoyazhizhou.github.io/socio-protocolics/)。它由[网站构建工具](../tools/build_site.py)按公开清单生成，分章页面来自SSOT的九组标签，不回写或拆分权威正文。网站输入与输出都位于忽略的`.local`构建目录；不递归复制工作区。

本地安装与构建：

```powershell
python -m pip install -r tools/requirements-site.txt
python tools/build_site.py
python tools/test_build_site.py
python tools/check_site.py
python -m http.server 8000 --directory .local/site-build
```

构建采用严格模式；Markdown内的公式竖线只在派生输入中转换为等价LaTeX分隔符，以免被识别为表格列。站内分章链接保留通往完整正文的既有锚点。数学渲染加载固定版本MathJax的公共CDN资源，部分图表也需要浏览器加载渲染资源；无法联网时不能保证这些呈现，但权威Markdown仍可下载阅读。

[Pages工作流](../.github/workflows/pages.yml)在`main`或`codex/public-release`收到提交时执行公开内容门禁、构建和部署，也支持手动触发。仓库管理员须先将GitHub Pages发布源设为GitHub Actions；凭据放在GitHub/本机凭据系统，不写入仓库。远程推送、Actions成功与网站可访问分别核验，不以本地构建成功代替发布成功。
