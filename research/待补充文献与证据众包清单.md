## 一、 为什么我们要公布“证据缺口”？

《社会系统协议学》恪守【红线⑧：认识论审慎与实证边界】与【红线⑨：真实案例先行与反向检验】。在第一轮全书 8 章及附录的严密内审中，我们坚决反对“把假说包装成定律”、“把二手转引冒充一手核验”。

因此，我们在本清单中明确列出全书目前**最急需外部专家与学术社区协助补充的四类硬核材料**。凡提供经核验有效的文献、档案影印或代码复现者，将在白皮书相应章节尾注、修订记录及致谢名单中**永久署名鸣谢**。

## 二、 证据采纳分级标准 (Evidence Grading Standard)

提交的材料将由学术评审团队按以下标准进行定级采纳：

| 证据等级 | 认可范畴与凭据要求 | 适用采纳场景 |
| :--- | :--- | :--- |
| **A 级证据 (Primary Verification)** | 历史档案原件扫描件/高清影印（公报、地方志善本、奏折）、权威数据库原刊（JSTOR / ScienceDirect / Oxford Academic 等）全文与精确页码、官方统计年鉴原始表格、开源可复现的计量代码与数据集。 | 可直接作为白皮书承重事实，核销台账缺陷，支撑核心命题。 |
| **B 级证据 (Authoritative Secondary)** | 中华书局/商务印书馆点校本正史明确卷次与条目、国内外顶级同行评议期刊（QJE / AER / JPE / 历史研究 / 经济研究）论文明确转引、权威断代史专著。 | 可作为支撑性说明与背景证据，标注为“权威二手续证”。 |
| **C 级证据 (Candidate Lead)** | 学术回忆录、报刊报道、网络公开线索、非权威机构报告。 | 仅作为候选研究线索（Working Lead）登记，不单独承担理论证明责任。 |

## 四、 如何认领任务与提交贡献？

参与学术证据补全非常简单，遵循标准的 GitHub 开源协作流程：

### 1. 认领任务
- 在本项目的 GitHub Issues 页面，新建一个 Issue，标题格式为：  
  `[Task Claim] 认领任务编号：例如 W-HIST-01 教育部公报影印`
- 在 Issue 中简述你目前已掌握的检索渠道或已有资料，避免多人重复劳动。

### 2. 提交材料 (Pull Request)
- 将你取得的高清影印 PDF、文本引文出处、或计量脚本放置在 `research/evidence_inbox/` 对应任务目录下；
- 提交 Pull Request，附带简明的**《证据核验说明》**：
  ```markdown
  ### 任务编号：W-HIST-01
  - 材料名称：《教育公报》第七年第二期公牍第12页
  - 来源渠道：国家图书馆民国期刊库扫描件（附条目号与分辨率说明）
  - 关键原文句定位：第三行“令国民学校一二年级先改语体文...”
  - 对白皮书的修正建议：验证了第5.4节令号准确无误，建议在附录证据卡附上此高清书影。
  ```

### 3. 验收与致谢
- 本项目学术编辑与主理人将在 3 个工作日内完成原件独立比对；
- 验收通过后，合并进入主分支，并在以下位置永久体现贡献：
  1. 白皮书相应章节的学术引注直接注明：`“感谢 [贡献者名/GitHub ID] 检索并提供本件档案”`；
  2. 记入本仓库公开的 `CONTRIBUTING.md` 荣誉贡献者名录；
  3. 在本清单中将该任务状态标记为 **🟢 已结项** 并展示关闭依据。
