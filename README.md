## 社会系统协议学研究什么？

人类大规模协作依赖语言、契约、组织审批、法律执行与公共规则。制度经济学、历史社会学与政治学（如奥尔森的制度硬化、泰恩特的复杂性递减、基德兰德与普雷斯科特的动态不一致、诺斯与温加斯特的可信承诺、蒂利的国家形成、斯科特的国家可读性、哈耶克的分布式信息、图费克奇的网络动员）积累了丰富的机制解释，但不同学科的概念接口往往彼此割裂；与此同时，分布式计算、操作系统与网络工程在处理高并发协作、权限隔离、故障恢复与遗留系统迁移时，已经形成了一套清晰的分析原语。

**社会系统协议学（Socio-Protocolics）**将这些系统工程概念与主流社科问题对齐，采用**双轨分层统一著作**体例（L1 传播层系统工程白话 + L2 理论层多智能体协议原语），围绕六组核心问题组织建模、案例比较与可证伪检验：

1. **信道容量与语义边界（第 I 组）**：表达方式与命名规则如何影响理解成本与协作扩散？为什么胡适白话文运动等底层表达改革能降低读写与传播门槛，而另一些标准只停留在纸面上的正式采用？
2. **中介寄生与兼容层衰减（第 II 组）**：组织与制度中的中间件提供的是必要的转译、认证与协调服务，还是演化成了排他控制与非生产性租金提取的关口？删掉两道审批后，协调工作真的变少了吗？
3. **跨期终局性与预期信誉（第 III 组）**：契约执行、违约回收与记录持久性如何塑造跨期终局性，进而影响主体的预期与长期不可逆投入？
4. **特权环隔离与脑裂传染（第 IV 组）**：如何通过权限边界（类比 Ring-0/Ring-3）、独立复核与救济约束规则执行者自身？资源断流、多头冲突指令（脑裂）与退出门槛如何改变博弈均衡？
5. **传输拓扑与任务反馈（第 V 组）**：大规模信息动员为什么不自动转化为持续治理能力？确认回执（ACK）、资源补给与纠错闭环如何配合？
6. **技术债核算与演化筛选（第 VI 组）**：面对沉重的历史制度包袱（技术债），如何核算推倒重写与增量绞杀式旁路迁移（Strangler Fig）的净负担？在有限预算下，民间多分支并行试验与成熟反馈筛选何时优于单一顶层设计？

### 框架结构与认识论边界

- **三层建模导航（`3 → 6 → 19`）**：基于 **5 大基石原语**（`O1` 智能体、`O2` 协议规范、`O3` 预期与信任、`O4` 中介解释层、`O5` 物理硬约束），由 **3 条第一性公设（P1–P3）** 组织 **6 组核心命题（I–VI）** 与 **19 项有效 SP-RFC 条款（001—019，其中 003 为语义传播应用、007 为跨组规范守则、019 为第八章跨组工具与研究规范，另保留 2 项非编号材料）**。层级箭头表示建模依赖与条款归属，不表示从三条公设已严格证明全部命题。
- **开放研究纲领而非已证普遍定律**：这是一个接受修订与反例检验的研究纲领。工程类比帮助压缩表达与提出问题，不直接等同于数学证明或社会同构；物理定理引用、形式条件命题、经验机制假说、核算定义与规范守则分别需要各自的证据；第八章的测量指标与参考代码属于**概念形式化架构参考规范与未来实证研究议程**，不宣称已完成社会实测或具备预测能力。
- **当前审读进度**：[在线阅读网站](https://nuoyazhizhou.github.io/socio-protocolics/)由相同公开 Markdown 自动生成，支持分章阅读、全文搜索与公式呈现。当前进入白皮书的逐章讨论与增量修订：每轮聚焦一章内的具体问题，按需读取相关正文、定义与证据卡，讨论结论与实际修改分开记录。当前章节、未决问题和下一项统一见[逐章进度](ROADMAP.md#chapter-review)，不以安装好分块工具或门禁通过表示章节已经审读完成。

## 仿真沙盘与实验工具 · Socio-Engine

理论不仅停留在白皮书文本中，本项目已实装了高性能的**社会系统协议多智能体仿真沙盘（Socio-Engine）**，用于对历史真实制度变迁与微观/宏观博弈进行可复现的沙盘推演：

- **双层架构 (Dual-Layer Architecture)**：底层采用原生 Rust（`socio_core`）严格强制执行双式记账物理守恒（银两/粮食/土地）、四大特权环隔离门禁（Ring-0 到 Ring-3）与 Petgraph 社会拓扑爆炸半径分析；上层采用 Python Agent-as-Data 架构，通过大模型（DeepSeek / Claude / GPT）模拟各阶级具有私有效用 $U_i$ 与生存底线的自博弈。
- **万历徽州赋役历史基准实验**：基于《万历歙县志》与《丝绢全书》真实赋税底册，完成了多组具有理论收敛性的推演（包含常规顾知县的自博弈、海瑞朴素整肃引起的胥吏怠工反弹、以及海瑞通过“去中介化（Dis-intermediation）”用寒门生员替代老吏的制度性突破，与全要素架空消融实验）。
- **跨朝代与跨文明剧本扩展**：提供自包含公理微内核的通用剧本生成提示词模板，支持学者与开发者一键将北宋王安石青苗法、唐代两税法、明代一条鞭法等历史改革编译为可运行的多智能体沙盘。

## 案例怎样回到理论

每篇案例区分四件事：外部材料说了什么、本文借用了什么概念、增加了什么假设、哪些观察会迫使我们修正。文章获得关注不等于框架得到验证；反例、零增益和已有更好解释，都应进入修订记录。

[开放研究库](research/README.md)接受独立研究者选择材料与方法，支持、反驳或收窄具体子主张。作者提供可检查的问题与来源起点；研究结果按证据回写候选假说及必要的白皮书条文，不以支持整体框架作为参与条件。

胡适案例首先提出理解成本、正式采用和样本扩散问题；这些仍是待比较的局部解释，没有据此宣布公设或六组核心命题获证。[案例与白皮书的对应关系](articles/hu-shih/来源说明.md#与白皮书的对应关系)列出具体边界。

中介主题已有待真实案例重构的概念样章、浙江单项登记材料、外国研究局部核对及OP-001虚构题包；尚未通过真实案例稿验收。统一要求见[案例驱动写作与命题检验](docs/案例驱动写作与命题检验.md)。文章区分工作去向、服务与关口；OP-001直接追问工程表示相对普通成本清单是否减少判读错误。两者均没有本项目的效果数据，也没有据此验证第二组全部机制。

后续同时整理中国与外国的采用、受阻及撤回案例，先区分正式进入、实际采用、理解效果和转换成本，再比较机制。所有面向读者的原创文档先有中文版本，再逐篇制作英文对应稿；两种语言保留同一组案例。[双语与写作约定](docs/双语与写作约定.md)规定版本同步和文章连接方式。

本地工作材料不属于公开目录。要求 Python 3.10+，首次安装参考引擎依赖后运行两类检查：

```powershell
python -m pip install -r tools/requirements.txt
python tools/verify_all.py
python tools/check_public.py
```

`verify_all.py` 检查公开文档的指定结构、文本边界和参考代码；默认不读取内部版。维护者的内部版检查方式见 [AGENTS.md](AGENTS.md#四-自动化质量门禁verification-gate)。需要不含旧 Git 历史的文件包时运行 `python tools/export_public.py`。具体边界见[发布与目录约定](docs/发布与目录约定.md)。这些检查不替代文献核查、数学证明或经验检验。
